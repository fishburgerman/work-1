# UI リニューアル計画 — Mac Native × Midnight Calm

作成：2026-11-16

## 1. 現状の調査結果

| 項目 | 内容 |
| --- | --- |
| 構成 | React 18・TypeScript・Vite・Tailwind CSS v4・lucide-react（線画アイコン。追加のライブラリは不要） |
| 色の指定 | 各画面の JSX に Tailwind のクラスを直接記述（約 60 ファイル・約 2,500 か所）。ほぼすべてが `navy-*`（アクセント・ダークの背景）・`slate-*`（文字・境界・ライトの背景）・状態色（`emerald`・`amber`・`red`・`blue`・`violet`）と、その `dark:` の組み合わせ |
| 色の仕組み | Tailwind v4 は色のクラスを CSS 変数（`--color-navy-900` など）に変換する。Phase 10 で、文字のコントラストのために `slate-400/500` をモードごとに上書き済み |
| 共通部品 | `ui/primitives.tsx`（ボタン・カード・バッジ・入力欄・見出し・空の状態）、`ui/Modal.tsx`、`ui/Toast.tsx`、`ui/notices.tsx`、`app/Layout.tsx`（PC のサイドバー・スマホのヘッダーと下部ナビ） |
| テーマ | ライト／ダーク／端末設定の3つ（既定は端末設定）。描画前に `public/theme-init.js` で適用 |
| 検証の仕組み | E2E で全画面・主要なダイアログに axe（WCAG 2.2 AA・コントラストを含む）をライトとダークの両方で実行。性能の計測（`PERF=1`） |

## 2. 方針

**色の値の層（デザイントークン）から変える。** 60 ファイルのクラスを書き換えるのではなく、クラスが参照する CSS 変数を新しいパレットに置き換える。

- 理由：①全画面が一度に統一される ②機能・データ・業務ロジックに触れない ③描画の性能が変わらない（CSS 変数の値の変更だけ）④変更の範囲が `index.css` と共通部品に集まり、元に戻しやすい
- `navy`（元の紺）は役割で置き換える：ダークでは 950〜700 を背景・面・境界のチャコール、500〜50 をセージグリーンのアクセントに。ライトではセージの濃淡に
- `slate` を、青みのある灰色から macOS に近い中立の灰色へ
- 状態色は、彩度を落とした指定の色（成功・アクセント `#8FA89A`／警告 `#C5A77A`／エラー `#C78383`）を基準に、濃淡を生成する。`blue`・`violet` も彩度を落とす
- **すべての文字の組み合わせを WCAG AA（4.5:1）で確認してから適用する**（既存の axe の検査が両モードで通ること）

その上で、トークンでは表せない部分（形・余白・配置・動き）を共通部品で直す。

## 3. 変更の内容

| 対象 | 変更 |
| --- | --- |
| パレット（`index.css`） | 指定の色：背景 `#1C1C1E`・サイドバー `#252528`・面 `#2C2C2E`・ホバー `#343438`・境界 `#3A3A3C`・文字 `#E5E5E7`／`#A1A1A6`／`#85858B`・アクセント `#8FA89A`。ライトも同じ考え方（`#F5F5F7` の背景・白の面・中立の灰色・濃いセージ） |
| テーマの既定 | ダーク（「ダークモードを基本」）。ライト・端末設定は従来どおり選べる |
| 文字 | `-apple-system, BlinkMacSystemFont, "Segoe UI"` ＋日本語（ヒラギノ・Noto Sans JP など）。太字を控える（bold を 600 に）。見出しを小さく（画面の見出し 20px） |
| 形 | 角丸を控えめに（ボタン・入力 8px、カード・ダイアログ 10px）。影をほぼ無くし、境界線で区切る |
| アイコン | lucide の線幅を 1.75 に統一。色は灰色、選択中・主要な操作だけアクセント |
| サイドバー | 幅 240px。**折りたたみ（64px・アイコンのみ）** を追加し、状態を端末に保存。選択中の項目だけ控えめな背景。日付・テーマの切替は下部へ |
| ツールバー | PC では画面の見出しと主要な操作（新規作成など）を、上部に固定するツールバーにする（スクロールしても操作に届く） |
| ボタン | 標準は灰色、主要な操作だけアクセント（文字は暗色でコントラストを確保）。影・発光なし |
| 入力欄 | 面の色の背景・薄い境界・フォーカスは控えめなアクセントのリング。エラーは色＋文言（既存） |
| ダイアログ | 背景のぼかしを無くし、角丸・余白を macOS のダイアログに近づける。キーボード操作・フォーカスの閉じ込め（既存）は維持 |
| 通知（トースト） | 小さく。成功・失敗・情報をアイコン・文言・色で区別（既存の区別を維持） |
| 動き | ダイアログ 180ms・通知 150ms・ホバー 150ms。移動量を小さく。「動きを減らす」設定は既存の対応を維持 |
| グラフ | 状態色を彩度の低い色に（凡例・件数の併記は既存） |

## 4. 変更しないもの

- データ構造・データベース・業務ロジック・画面遷移・検索条件の保持・下書きの保持・郵便番号・電話番号の補助・大量データの表示（段階表示・索引）
- 画面・機能の追加（右側の詳細パネルは、既存の画面に該当する一覧＋詳細の構成がないため追加しない。詳細は既存の詳細画面・ダイアログのまま）
- アクセシビリティの名前（テストとスクリーンリーダーが使う名前）。サイドバーを折りたたんでも項目名は読み上げられる

## 5. 進め方と検証

1. パレットを生成し、主な文字と背景の組み合わせのコントラストをスクリプトで確認
2. `index.css` のトークン・共通部品・レイアウトを変更
3. 主要な画面をスクリーンショットで確認（PC・スマホ、ダーク・ライト）
4. 型チェック・単体テスト・E2E 全体（axe の両モードの検査を含む）
5. 性能の計測（変更前後でタスク一覧・保存が遅くなっていないこと）
6. 結果を `docs/UI_RENEWAL_RESULTS.md` に記録

ダッシュボードのカードの数を減らすなど、画面の構成を変える改善は、今回のトークン・部品の変更の後に、画面ごとに段階的に行う（次の段階）。
